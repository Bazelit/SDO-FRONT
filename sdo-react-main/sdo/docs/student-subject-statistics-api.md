# Статистика по предметам: интеграция frontend/backend

Кабинет студента принимает нормализованные frontend-данные по каждому предмету:

- стабильный идентификатор предмета и отображаемое название;
- количество сданных заданий;
- общее количество заданий, входящих в статистику.

Процент выполнения рассчитывается на фронтенде как отношение сданных заданий
к общему количеству. Для предмета без заданий показывается отдельное состояние,
а не 0% выполнения. Адаптер API должен преобразовать согласованный ответ
backend в эту модель. Перечисленные выше понятия относятся только к модели
frontend и не задают названия полей ответа API.

Endpoint и контракт ответа пока не определены. Текущий сервис явно сообщает,
что интеграция не подключена; фиктивные данные и предполагаемый URL не
используются.

Вопросы backend-разработчику:

1. Каковы endpoint и HTTP-метод для получения статистики авторизованного
   студента? Нужно ли определять студента и учебный период по access token?
2. Какие статусы заданий считать сданными: отправленные, принятые,
   успешно проверенные или другой набор?
3. Какие задания включать в общее количество: все задания курса, только
   активного/текущего периода или другой набор?
4. Нужна ли на дашборде оценка/балл помимо процента выполнения? Если да,
   каков её источник и правило расчёта?
5. Как API отличит предмет без заданий от отсутствующей или недоступной
   статистики?
6. Какой ответ возвращается, если у студента нет предметов, и какие ошибки/
   HTTP-статусы должен обрабатывать frontend?
